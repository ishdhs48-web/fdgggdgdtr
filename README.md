# models — deepseek bridge

Сайт с выбором модели: выбираешь файл инструкций — он уезжает в DeepSeek как системный
промпт, дальше обычный чат. Работает через **веб-сессию chat.deepseek.com по токену**, без
платного API. В браузере это unlimited, по токену — то же самое.

## Запуск

Двойной клик по `start.cmd` (или `cd app && node server.mjs`).
Откроется http://127.0.0.1:8770

Токен уже вписан в `app/config.json`. Если когда-нибудь протухнет — на сайте
chat.deepseek.com открой DevTools → Console:

```js
JSON.parse(localStorage.getItem('userToken')).value
```

и вставь строку в модалку, которая появится сама.

## Что внутри

```
deepseekddd/
├─ *.md                  ← инструкции моделей (их и выбирает сайт)
├─ start.cmd
└─ app/
   ├─ server.mjs         ← http-сервер + SSE-прокси к DeepSeek
   ├─ config.json        ← токен, порт, дефолтная модель, флаги
   ├─ sessions.json      ← история чатов (создаётся само)
   ├─ lib/
   │  ├─ deepseek.mjs    ← клиент completion + парсер SSE
   │  ├─ pow.mjs         ← пул воркеров, кэш решённых PoW
   │  ├─ pow-worker.mjs  ← воркер
   │  └─ models.mjs      ← чтение .md из папки выше
   ├─ vendor/
   │  ├─ pow-bundle.js   ← официальный solver DeepSeek (как есть)
   │  └─ pow-chunk.js
   └─ public/            ← UI (index.html, app.js, styles.css)
```

## Как это работает

1. `POST /api/v0/chat/create_pow_challenge` → challenge.
2. Воркер решает `DeepSeekHashV1` (их же бандл, без изменений).
3. Решённый ответ кладётся в заголовок `x-ds-pow-response` (base64 JSON).
4. `POST /api/v0/chat/completion` стримит SSE — сервер режет его на дельты и отдаёт в UI.

PoW-ответ одноразовый (`INVALID_POW_RESPONSE` на повторе), поэтому сервер решает следующий
заранее, пока ты читаешь ответ: первое сообщение стартует за ~60–100 мс, а не за 5–15 с.

**Модель = первый промпт.** Файл `.md` уходит целиком перед твоим сообщением. Дальше
DeepSeek помнит контекст сессии — инструкции повторно не отправляются. Если переключить
модель в том же чате, сервер поднимает чистую сессию, кладёт новые инструкции и прицепляет
переписку как `<conversation_so_far>`.

**thinking включён всегда выключенным** (Deep thinking off), **Smart Search включён** —
так и просил. Оба тумблера есть в шапке, если надо иначе.

## Настройки (`app/config.json`)

| ключ | смысл |
|---|---|
| `token` | веб-токен DeepSeek |
| `deviceId` | `x-device-id`, стучит вместе с токеном |
| `defaultModel` | что выбрано при старте |
| `defaultThinking` | Deep thinking (по умолчанию `false`) |
| `defaultSearch` | Smart Search (по умолчанию `true`) |
| `resendPromptEachTurn` | `true` = инструкции уходят в каждый запрос, а не один раз |
| `port` / `host` | где слушать |

## Модели

Список = все `*.md` в `deepseekddd/`. Положил новый файл — он появился в списке после
перезагрузки страницы, код трогать не надо.

Ограничение одно: файл должен влезать в один промпт. Самый большой тут ~653 000 символов —
проходит (проверено), но дальше по длине уже начнёт упираться в лимит контекста DeepSeek.
